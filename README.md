# Todo List 線上協作系統

專為團隊協作打造的輕量化、即時同步 Todo List 線上系統，具備免密碼 Email 白名單登入、多維度分類與指派、即時狀態同步等功能。

---

## 一、 核心功能需求

### A. 登入與成員管理
1. **免密碼 Email 登入**：使用者僅需輸入 Email 即可快速登入。
2. **白名單權限控制**：系統維護允許登入的 Email 白名單，僅在白名單內的成員享有進入系統的權限。
3. **個人暱稱自訂**：登入後，成員可設定與修改個人顯示暱稱（Display Name），方便任務指派與識別。

### B. Todo 待辦事項功能
1. **分類與標籤管理**：
   - 支援建立、自訂不同類別與顏色標籤。
   - 待辦事項可明確歸類於特定類別。
2. **截止時間**：每筆待辦事項皆可設定預計到期與截止日期時間。
3. **負責人指派**：可從白名單成員清單中下拉選擇該事項的負責人。
4. **完成狀態**：提供 Checkbox 勾選功能，勾選完成後自動套用完成樣式（文字刪除線、淡化效果）。

### C. 頁面呈現與操作
1. **完成項目過濾**：提供切換開關，可一鍵「隱藏」或「顯示」已完成的待辦項目。
2. **多維度排序**：支援依照以下條件動態排序：
   - 建立日期（由新到舊 / 由舊到新）
   - 分類類別
   - 截止日期（即將到期優先）
   - 負責人

## 二、 系統架構評估與架設建議

### 1. 為什麼不能只用 GitLab Pages + txt 紀錄？
- **GitLab Pages 為純靜態託管**：伺服器只負責傳送靜態 HTML/CSS/JavaScript，無法在伺服器端執行 Node.js/Python 等後端服務，也沒有直接寫入本機檔案（txt）的能力。
- **多人協作需即時同步**：若單靠本機儲存（LocalStorage）無法達成跨裝置與多人即時共用。

### 2. 建議採用的架構：方案 2【GitLab Pages ＋ 免費雲端資料庫（Supabase）】
本專案採用 **GitLab Pages（前端靜態部署）** 搭配 **Supabase（免費雲端資料庫）** 的無伺服器（Serverless）架構：

- **前端部署**：託管於 GitLab Pages，零主機維護成本，透過 `.gitlab-ci.yml` 實現推程式碼自動發布。
- **資料儲存與同步**：
  - 使用 Supabase（基於 PostgreSQL 的現代化 BaaS），免費額度充裕且穩定。
  - **即時多人協作（Realtime）**：當任一成員新增、編輯或勾選完成時，其他成員的螢幕立即自動同步更新，無須手動重新整理頁面。
  - **安全與白名單驗證**：透過資料庫存取規則與使用者白名單表，精確控制登入成員的讀寫權限。

## 三、 資料庫結構規劃 (Database Schema)

預計建立三張核心資料表：

1. **`users_whitelist`（使用者白名單）**
   - `id`：識別碼
   - `email`：授權的 Email（唯一鍵）
   - `display_name`：自訂顯示暱稱
   - `role`：角色（管理者 `admin` / 一般成員 `member`）
   - `created_at`：建立時間

2. **`categories`（分類標籤）**
   - `id`：分類 ID
   - `name`：分類名稱（例如：日常、開發、緊急等）
   - `color`：標籤顏色代碼

3. **`todos`（待辦事項清單）**
   - `id`：待辦項目 ID
   - `title`：事項標題 / 內容
   - `category_id`：所屬分類 ID
   - `assigned_to`：負責人（對應使用者 Email / ID）
   - `due_date`：截止日期與時間
   - `is_completed`：是否已完成（布林值）
   - `created_by`：建立者
   - `created_at`：建立時間

## 四、 實施計畫與步驟

1. **階段一：前端系統開發**
   - 建立現代化高質感的 Todo List 介面（響應式 RWD、深淺色調與流暢微動畫）。
   - 實作 Email 白名單登入、暱稱設定、Todo CRUD、多維度排序、隱藏已完成等邏輯。
2. **階段二：Supabase 資料庫設定**
   - 撰寫一鍵執行的 SQL 建表腳本（包含 RLS 安全原則與 Realtime 廣播功能）。
   - 前端串接 Supabase JS SDK，實現多人即時同步。
3. **階段三：GitLab CI/CD 與 GitLab Pages 自動發布**
   - 撰寫 `.gitlab-ci.yml` 設定檔。
   - 推送至 GitLab 儲存庫，驗證自動打包並正式上線。
